# 基金筛选的候选池取自排行表，风险指标在预选集内计算

fund_screening 需要一个可筛选的基金全集：Go 订阅池（原 `issuse.md` 首选方案）只有几十只已订阅基金，筛选没有「发现」价值；而全市场 2 万+ 基金无法实时逐只拉净值算风险指标。**决定**：候选池取自 collector 排行表端点（akshare `fund_open_fund_rank_em`，按主类切分，1 次/类型调用，自带近1/2/3年等收益列）；候选池级只做类型与区间收益的确定性预筛，按锚点选出预选集 Top M（M=30）；回撤/夏普/波动率仅对预选集经现有 collector→analyzer 链路计算并在 finalize 内过滤，报告强制披露预筛锚点与样本偏差。agent 不新增到 Go server 的取数通道，数据边界保持 collector 单一来源。

理由：架构零新通道、保住「发现新基金」的产品价值、完整复用现有采集/分析/证据与测试基建；风险字段候选池级缺失用「锚点 + 偏差披露」诚实处理而非隐瞒。

## Considered Options

- **以 Go 订阅池作候选池（agent→Go 只读客户端）**：风险字段在全候选池真实可筛，但覆盖极小，且需扩展数据边界与跨语言契约。被否。
- **纯收益档筛选（不做两段式）**：最简，但「低回撤/高夏普」类查询全部进 unsupported，旗舰用例哑火。被否。
- **预计算全市场因子表（原 issuse.md 方案 C）**：真正的候选池级风险筛选，但需 2 万+ NAV 定时批任务，工程量大；后置为 Step 3 增长路径——届时仍是 collector 侧纯 Python 实现，Go 依旧不参与。

## Consequences

- 预筛锚点与 M 是产品语义的一部分，报告不允许静默。
- 未来接入因子表后，finalize 的预选集级风险过滤可升级为候选池级硬过滤，工作流形状不变。
